# 살아봄 데이터 연동

UI의 기존 스타일과 경로를 유지하고 공공데이터 표시를 연결했다. 런타임 상세 결과는 `runtime-audit.json`에 저장하며 인증키는 기록하지 않는다.

## 확인한 공식 명세

- 방문자: https://www.data.go.kr/data/15101972/openapi.do — 첨부 `TourAPI_Guide_(관광빅데이터)v4.1.zip`의 기초 지자체 명세. `MobileOS`, `MobileApp`, `serviceKey`, `_type`, `startYmd`, `endYmd`, `pageNo`, `numOfRows`. 지역 요청 변수는 없어 응답의 `signguNm`으로 필터링한다. 추출한 명세는 `visitor-guide.txt`.
- 축제: https://www.data.go.kr/data/15013104/standard.do — `https://api.data.go.kr/openapi/tn_pubr_public_cltur_fstvl_api`; `type=json`과 페이지 변수. 전국 자료를 페이지 끝까지 읽고 주소의 시도·시군구를 정확히 비교한다.
- 도서관: https://www.data.go.kr/data/15013109/standard.do — `https://api.data.go.kr/openapi/tn_pubr_public_lbrry_api`; 지역 필터는 대문자 `CTPRVN_NM`, `SIGNGU_NM`. 응답의 camelCase와 UPPER_SNAKE_CASE 필드를 지원한다.
- 농어촌 체험: 사용자 제공 공식 요청주소 `https://api.data.go.kr/openapi/tn_pubr_public_frhl_exprn_vilage_api`; `ctprvnNm`, `signguNm`으로 조회하고 응답도 지역을 검증한다. 제공되지 않은 이미지나 Wi-Fi 정보는 생성하지 않는다.
- TourAPI: 루트 `areaCode2`는 `areaCode`를 생략한다. 반환된 시도·시군구 이름으로 코드를 해결하며 시군구 코드를 하드코딩하지 않는다.

## 산식과 해석

- 지역 활력: 가장 최근 조회 가능한 월말의 외지인 단일 구분, 단일 일자 값으로 `round(min(100, log10(1 + 방문자값) / 6 * 100))`. 이는 자체 비교 지표이며 공식 관광객 통계나 월간 순방문자 수가 아니다. 최근 3개 월말을 순서대로 조회해 공표 시차를 처리한다. 날짜와 구분을 UI에 표시한다.
- 지역 주거비 수준: 직전 완료 월부터 6개월, 아파트·오피스텔 각각 전체 페이지. 거래별 `월세 + 보증금 × 0.04 / 12`의 중앙값(원). 연 4%는 보증금 기회비용 비교 가정이며 법정 전환율이나 숙박 견적이 아니다. 보증금·월세 중앙값과 거래 건수도 별도 표시한다. 전세의 월세 0도 유효하다. 부담 점수는 `round(100 / (1 + 월환산비용 / 1000000))`.
- 적합도: 기존 주거 점수를 실제 주거 부담 점수로 대체하고 종합 점수 변화에 15% 반영. 도서관 수 기반 지표를 기존 워케이션 점수에 20% 반영하고 종합 변화에 10% 반영. 지역 활력은 중립 50점 대비 차이를 종합 점수에 10% 반영. 성공한 소스만 점수에 반영한다. 도서관 수는 인터넷 품질을 뜻하지 않는다.
- 축제: 종료일이 지난 행사는 상세에서 ‘지난 행사’로 표시. 지도·생활 플랜에서는 진행·예정 행사만 노출한다. 일정 미제공 행사는 현재 행사로 취급하지 않는다.
- 일부 주택 조회 실패 시 제한된 표본은 FALLBACK이며 사유와 실패 월/유형을 보존한다. 모든 빈 월 조회 후에만 EMPTY로 분류한다.

## 화면 연결

홈·비교·상세·적합도에 지역 활력, 상세·비교·생활비 카드·적합도에 주거비를 연결했다. 상세의 프로그램/생활 인프라 탭과 펼침 목록, 지도와 생활 플랜의 펼침 목록에서 축제·농어촌 체험을 제공한다. 도서관은 상세·지도·워케이션 점수에 반영한다. 제공 좌표로 외부 지도 링크를 연다. 기존 지도 배경은 개략도이며 정확한 위치는 링크에서 확인한다.

## 검증

`npm run build`, `npm run lint`. 브라우저 런타임 감사: Vite를 127.0.0.1:5174에서 실행하고 `node scripts/runtime-audit.mjs`. Edge headless를 사용한다. 5개 지역 집계, TourAPI 코드 해결/HTTP/응답 구조, 화면 표시, 중앙값·금액단위·응답 형태·불일치·지난 행사 처리를 검사한다.

운영 배포 시 `/api/*`에 개발 서버와 동일한 프록시가 필요하다. 현재 검증 범위는 로컬 Vite 런타임이다.
